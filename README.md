# 三体人的万年历

原生 macOS 三星及多天体引力模拟与行星纪元历法。应用使用 SwiftUI、AppKit、MetalKit 和
REBOUND IAS15，计算在后台运行。全部计算与项目文件均在本机，不需要联网账户。

## 构建与启动

需要 macOS 14 或更新版本，以及支持 Swift 6 的 Xcode Command Line Tools。
首次运行前可在终端通过 `xcode-select --install` 安装 Apple 开发工具。
REBOUND 源码已固定版本并包含在仓库中，构建不下载第三方依赖。

在项目根目录执行：

```sh
./script/build_and_run.sh
```

`dist/三体人的万年历.app`；生成的应用可以在 Finder 中双击打开。
所有构建缓存位于项目内的 `.build`。

```sh
./script/build_and_run.sh --verify     # 构建、启动并确认进程
./script/build_and_run.sh --build-only # 只生成应用包
./script/build_and_run.sh --debug      # 使用 LLDB 启动调试
./script/build_and_run.sh --logs       # 启动并查看应用日志
./script/build_and_run.sh --telemetry  # 启动并筛选应用日志子系统
```

默认生成优化后的 Release 构建；`--debug` 使用调试构建。也可显式选择：

```sh
TRISOLARIS_BUILD_CONFIGURATION=release ./script/build_and_run.sh
```

本地应用使用 ad-hoc 签名

### 在本机 Xcode 中编译

1. 安装完整 Xcode，在终端用 `xcodebuild -version` 确认当前开发工具可用。
2. 在 Xcode 中选择“文件 → 打开”，选中本目录的 `Package.swift`，不需要另外生成 `.xcodeproj`。
3. 选择 `TrisolarisApp` scheme 和“我的 Mac”，用“产品 → 构建”（`⌘B`）编译，
   或用“产品 → 运行”（`⌘R`）启动；用“产品 → 测试”（`⌘U`）运行单元测试。

Xcode 直接构建 Swift Package 可执行目标。要生成包含图标、许可和 `Info.plist` 的
完整 `.app`，请使用上面的打包脚本。

### 生成本地 Release 附件

```sh
./script/release.sh
```

`release.sh` 运行单元测试和 100 年数值检查，再构建 1.3.1 的 arm64 应用，
验证版本与代码签名，并在 `dist/` 中生成 `三体人的万年历.app` 和
`ThreeBodyCalendar-v1.3.1-arm64.dmg`。脚本会请 Finder 设置 DMG 窗口布局；
如 macOS 提示自动化授权，允许终端控制 Finder 后再运行。
打开 DMG 后，可将应用拖到“应用程序”文件夹。发布脚本不执行 Developer ID 签名或 Apple 公证。

## 使用

1. 工具栏保留四种不同用途的入口：宁静层级（唯一的稳定单星参考）、双日世界（环双星）、
   等质量八字（无行星）及随机初始轨道。重复的单星层级变体已从菜单移除，旧项目仍可打开。
   三星穿行候选的筛选记录保留在 [Validation](Validation/README.md)；
   菜单不提供尚未完成完整验证的候选。
2. 在右侧检查器编辑恒星和行星。支持质量、半径、光度、三维位置与速度，也可将
   二体轨道要素转换成初始状态。开始模拟后，每个天体受到全系统引力作用。
3. 选择参考恒星与适宜参考距离，设置历法年数、气候阈值、积分容差和环境采样数。
   默认计算一万个标准年。没有行星时可以观测三星，添加行星后可生成历法。
4. 使用观测页播放、暂停、单步、选择和跟随天体，或切换俯视。天体增强显示只影响
   画面，物理半径和碰撞判断使用真实配置值。增强半径在场景取景时固定，不因行星靠近而缩小恒星。
   图中不再添加跟随天体的文字，天体图例、勾选式跟随与俯视开关放在视图边缘。
   除四档固定速度外，第五项“手动滑轨”提供 0.003～30 标准年/秒的对数调速。
   显示轨迹每最多 1/120 标准年取真实积分状态，10 年/秒不会因此降低轨迹精细度。
   轨迹保留最近 2.5、7.5 或 20 标准年，播放越快，在屏幕上的消退时间越短。
5. 生成万年历后，默认按连续纪元区间合并显示和导出，不必逐年输出；需要时可切换年度明细。
   表格每页最多显示 200 条；分页不改变计算精度或导出的完整数据。大项目后台读取并显示加载状态。
   在历法页按年份或纪元筛选，并回放指定区间或年份；分析页显示温度、
   辐照、守恒误差和事件。可以运行严格精度复算比较年度标签。
6. 使用“文件”菜单保存 `.trisolaris` 项目、另存为、重新打开，或导出 CSV/JSON。
   计算可以暂停再继续；保存文件包含可用的计算检查点。取消或碰撞发生后，已经
   完成的年份仍可查看。场景也可导出 PNG。

主要快捷键：`⌘N` 生成混沌星海，`⌘O` 打开，`⌘S` 保存，`⇧⌘S` 另存为，`⌘G` 生成万年历，
`⌘R` 重置初始状态，`⌘.` 单步，`⌘Return` 开始/暂停观测，`⌘1/2/3` 切换页面，
`⇧⌘M` 切换箭头编辑模式，`⌘0` 重置视角，`⇧⌘T` 俯视，`⇧⌘F` 跟随，`⇧⌘E` 导出纪元 CSV。
`⌘W` 关闭当前窗口，最后一个窗口关闭时退出应用；未保存内容仍会询问保存。`⌘Q` 退出应用。
每个项目窗口持有独立配置和计算实例。

## 1.3.1 功能与修复

- 工具栏“真实星系”打开半人马座 α 的离线历史观测表；按天体和测量类型筛选、分页查看，选中记录可见原始时间及仪器。默认点击“导入并生成可运行场景”会导入 A、B、比邻星并加入一颗明确标为假设的实验行星，生成万年历即可使用；取消勾选可只导入三星。
- 观测页可切换手型与箭头。手型拖动旋转、Shift/右键拖动平移，滚动缩放；箭头直接拖动星体，沿屏幕平面保持深度，松开应用并从新状态开始计算，Esc 取消本次拖动。“撤销位置”恢复上一次位置编辑。更精确的三维坐标仍可在检查器输入。
- 天体列表的加号菜单可加入恒星或行星，减号删除所选天体，至少保留一颗恒星。随机轨道菜单增加“自定义数量”，恒星和行星数量可直接键入或使用步进器，总数最多 64 个。经典“混沌星海”在当前无行星时会补上一颗实验行星，也可按 `⌘N` 生成。全部天体参与引力，每次万年历针对一颗指定行星；随机初值不承诺稳定或宜居。

### 半人马座 α：实测与模型

内置 **18,113 条测量值**：106 对 A/B 方位角及角距（展开为 212 个数值，1940–2019）、
17,567 条 A/B HARPS 径向速度（2004–2018）及 334 条比邻星相对径向速度（2000–2019）。
原始误差、时间、仪器编码和来源一同保留，可离线查看。**这不是首次观测至今的完整历史档案**；
没有伪造更早或更新的观测，也没有把插值轨迹算作实测。

三维初值采用相互一致的 Kervella 2016/2017 参数，参考历元 J1991.25，三星质心静止，
坐标轴沿银河方向。观测表与连续模拟分别展示，不会自动用上传记录重新拟合轨道。
比邻星约 12,947 AU 的距离使 A/B 在全景中非常接近；选择 A 并跟随后缩放可观察内双星。
观测约束模型本身只包含三颗恒星。导入窗口默认加入的实验行星位于 A 星单星参考辐照距离，
由局部圆轨道给出初始速度，属于假设实验而非实测资料。
详细参数、时间换算、观测误差、下载地址与限制见
[数据来源说明](Sources/SimulationCore/Resources/ObservedSystems/alpha-centauri-provenance.md)。

“数据”菜单支持 UTF-8 CSV 导入及当前筛选的完整导出。新增记录随 `.trisolaris` 项目保存。
CSV 表头固定如下，可先导出内置记录作为格式模板：

```csv
epoch_year,component,kind,value,uncertainty,unit,source_url,detail
```

`epoch_year` 为用于显示排序的年份数值（1～9999）；精确原始时间、时标与转换方法请写在 `detail`。
类型使用 `positionAngle`（deg）、`separation`（arcsec 或 mas）、`radialVelocity` 或
`relativeRadialVelocity`（m/s 或 km/s），也接受应用导出的中文类型名。
误差未知时留空；`source_url` 必须是有效 http(s) 来源地址。每次最多 100,000 条、32 MB，
不会自动换算单位或混合不同仪器的零点。

## 科学模型与精度

### 引力

支持 1～64 个天体，至少一颗恒星。所有恒星与有质量行星共同构成牛顿 N 体模型，
行星对恒星及其他行星产生反作用。多行星时由“历法行星”选择当前计算对象。
内部单位为 AU、太阳质量和日，位置、速度及积分均使用双精度。
内核固定为 REBOUND 4.4.11，提交
`1509463f3e5802807e69dfd7db23ff4309c56909`。IAS15 自适应调整引力积分步长，
默认 `epsilon = 1e-9`，严格复算为 `1e-11`，编译禁用 fast-math 和浮点运算收缩。

有限半径天体发生碰撞时停止该模型，不自动合并。碰撞检测使用积分步内线性轨迹
检测；它比只检查画面帧更可靠，但仍是对一步内路径的数值近似。
能量、角动量及质心诊断用于发现数值异常。混沌系统的长期轨迹会放大初值和舍入
差异，良好的守恒量不等于任意长时间的轨迹都可作确定性预测。

层级三星是长期稳定候选，稳定结论以实际积分为准。八字轨道使用公开舍入初值；
已知周期性质针对理想等质量三星，改变质量、加入有质量行星或发生扰动后应重新
检验。八字初值来源见 [Richard Montgomery 的 N-body 页面](https://people.ucsc.edu/~rmont/NbdyB.html)。

### 标准年

一次计算开始时，按参考恒星与参考距离冻结标准年长度：

```text
T = 2π × sqrt(a_reference³ / [G × (M_reference + M_planet)])
```

“按地球参考辐照计算距离”将距离设为 `sqrt(L_star / L_sun)` AU。
这是该恒星单独供光时的参考尺度，实际环境同时合并所有恒星的辐照。
第 n 年覆盖 `[(n−1)T, nT)`，不使用地球公历的月份或闰年；行星换星后仍
使用同一个标准年连续计时。确认碰撞或远场逃逸后停止计算，保留已完成的时间区间。

### 逃逸终止

远离主星不等于离开三星系统。程序联合检查行星到每颗恒星的距离、相对其余天体质心的
向外速度及比能，并要求持续满足后才停止。采用的保守远场阈值至少 100 AU，且至少为
初始三星最大间距及参考距离的 10 倍；还须相对每颗恒星向外运动且具有正二体比能。
总势及逐星势能检查均要求至少 10% 余量，总势包含其余全部有质量天体；仍与另一行星束缚时不判定逃逸。
确认时长为 5 个标准年与局部最长外行时间 5% 的较大值。事件记录保留实际距离和确认时长。
这是有限时间的保守数值判定，束缚宽轨道和暂时的能量波动不会仅因距离大而被停止。

### 温度与纪元

总辐照为 `Σ L_i / (4πr_i²)`。辐射平衡温度考虑反照率和球面平均受光，再加上
固定温室增温，并通过一阶热响应体现热惯性。显示的是全球平均“模型温度”，
不代表完整气候预测。

默认规则均可在检查器修改：

| 设置 | 默认值 |
|---|---|
| 适宜模型温度 | 0～50 ℃ |
| 适宜总辐照 | 地球参考辐照的 0.7～1.5 倍 |
| 辐照波动上限 | 时间加权变异系数 20% |
| 辐照统计窗口 | 0.1 标准年 |
| 最短稳定持续时间 | 0.1 标准年 |
| 反照率 / 温室增温 | 0.3 / 33 K |
| 热响应时间 | 30 日 |
| 每标准年基础环境区间 | 256 次，严格复算 1024 次；每段检查中点并自动加密临界边界 |

温度、辐照及波动同时合格、且持续达到最短时长的区间才确认为恒纪元。
整个标准年被已确认的恒纪元覆盖才标记为“恒纪元年”；包含乱纪元区间的年份
标为“乱纪元年”，同时保留稳定时长占比。未完整计算的年度应视作待确认。
跨年不重置气候历史或稳定区间，末尾会继续计算必要的确认区间。

引力积分和环境采样是两种不同精度控制：降低 IAS15 容差不能代替加密气候采样。
临界阈值附近的纪元标签应结合更严格复算和采样收敛结果判断。
当前模型不包含完整大气、昼夜、季节、食与遮掩、潮汐、恒星演化或相对论效应。

## 验证与复现

```sh
./script/test.sh
./script/science_check.sh 10000 --output Validation/four-body-10000-optimized.json
./script/science_check.sh 10000 --kepler --output Validation/kepler-10000.json
```

测试入口用于数值基准、历法边界和存档一致性检查。已测得的结果和复现条件见
[验证记录](Validation/README.md)，耗时随初值、精度、设备和运行负载变化。
项目记录初值、规则、随机种子、内核版本及可恢复的积分状态。完整检查点在相同
内核版本和架构下用于继续积分；不同版本或机器架构不承诺逐位一致。
显示轨迹是有界抽样，历法统计使用更密的环境采样；显示抽样不等同于全部积分步。
项目文件编码、读取与写入均在后台；界面进度与结果限频刷新。
Metal 在侧栏尺寸变化时复用场景几何，合并缓冲区尺寸更新，避免在主线程等待积压帧。
